踩过的4 个坑

每个 Bug 都是一次对框架/工具理解的深化——这 4 个 v4.x 关键 Bug 的修复经历，是 Loci 工程化路上最值得分享的部分。

01
LANGCHAIN 1.x COMPAT
BM25Retriever API 变更
LangChain 1.x 移除了 get_relevant_documents()，必须改用 invoke()。混用新旧 API 会导致 TypeError，但堆栈信息往往指向错误位置，调试困难。
# 修复: retriever.invoke(query) 替代 retriever.get_relevant_documents(query)
02
BGE SIGMOID THRESHOLD
RAG Fallback 阈值未生效
v4.1 配置了 RAG_FALLBACK_THRESHOLD=0.3，但 _resolve_sources() 缺少判定逻辑，导致「数据库设计」问题检索到不相关 CIFAR-10 文档仍强行生成答案。
// 修复: 阈值 0.3→0.5（BGE 官方建议） + _resolve_sources() 加判定
03
STATEFUL SSE
「重新生成」按钮死代码
v4.0 「重新生成」按钮只刷新 UI，没有真正调用后端的 askQuestion({regenerate:true})。需先在 web_api.py 端增加 regenerate 字段透传到 rag_engine，再在前端真实发起 SSE 调用。
// 修复: 前端实际 SSE 调用 + 后端 query() 接受 regenerate 参数
04
PATH POLLUTION
doc.name 路径污染
v2.x FAISS 存储 doc.name 时混入相对路径（./uploaded_docs\file.pdf），API 透传到前端后路径显示混乱。需在 load_documents 阶段统一用 Path(p).name 提取文件名。
// 修复: doc.metadata["source"] = Path(file_path).name
